Sauvegarde et identité

Votre compte

La configuration Supabase est celle de l’application et ne doit être saisie qu’une fois par le propriétaire. Vos amis n’ont besoin que de leur e-mail et de leur mot de passe.

Ces deux champs concernent uniquement la configuration technique de l’application, pas la connexion des joueurs. Une fois l’URL et la clé publique intégrées dans SUPABASE_PROJECT puis publiée sur GitHub Pages, tes amis ne les verront plus et utiliseront seulement leur e-mail et leur mot de passe.

Configuration nécessaire dans Supabase

Créez un projet, exécutez tout le SQL fourni ci-dessous dans SQL Editor, puis déployez la fonction Edge open-booster depuis supabase/functions/open-booster. Sans ce déploiement, les ouvertures connectées sont volontairement refusées plutôt que de revenir à un tirage client falsifiable. Aucune clé service_role ne doit être placée dans cette page.


        

        
SQL sécurité et économie serveur
Ce bloc reste disponible même quand Supabase est déjà configuré. Copiez-le entièrement dans Supabase → SQL Editor, puis cliquez sur Run. Ensuite déployez open-booster avec supabase functions deploy open-booster. Le script remplace la sauvegarde vulnérable et ajoute les achats/ventes atomiques sans supprimer les données existantes.

        
Installation facultative du panneau admin
Cette migration ne supprime aucun profil ni aucune carte. Elle ajoute des fonctions SQL sécurisées et un journal d’actions; les commandes du panneau ne lisent pas le JSON complet de game_state. Exécutez ce script une seule fois après le schéma principal, remplacez ADMIN_EMAIL_HERE à la fin par l’adresse utilisée dans Supabase, puis actualisez l’application. Ne collez jamais de clé service_role ici.
